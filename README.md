# TelegramQuizArrangement

C# / .NET 10 бот для сбора участников воскресного квиза в Telegram.
Работает через HTTP Bot API и long polling, без сторонних библиотек.

## Поведение

Третий вариант выбирается по очереди: «Я Макс», «Не могу так далеко планировать»,
«Я в целом наквизился», «Мне всё с квизами понятно»,
«У меня есть более интересные дела (шпилить в комп)», затем снова первый.
Цикл общий для ручных и автоматических постов; позиция хранится в Docker volume
и сдвигается после успешной отправки. AI не генерирует этот вариант.

В группе команда `/start` или `/start@ИмяБота` создаёт нативный опрос:

```text
Играем в это воскресенье?
11-октября 19:00
```

- Ответы: **ДА**, **НЕТ**.
- Голосование открытое, с одним выбранным ответом; участники могут добавлять варианты.
- В описании опроса и кнопке под ним — маршрут Waze.
- В группах с темами опрос отправляется в тему, откуда пришла команда.
- В личном чате бот предлагает добавить его в группу.
- В новые группы бота может добавлять только владелец `Telegram:OwnerUserId`.
  При добавлении другим пользователем бот сразу покидает группу.
  Уже существующие группы сохраняются; `/start` доступна их участникам.
- Каждый вызов команды создаёт новый опрос. Недельное автоопросное расписание настраивается отдельно и не меняется ручными командами.

Дата вычисляется по `Asia/Dubai`: ближайшее воскресенье в 19:00, включая
текущее воскресенье до начала игры. В 19:00 и позднее выбирается следующая неделя.
Дата и время: `DD-MONTH HH:mm`, например `11-октября 19:00`. Название месяца полное, на русском.

Место: **Harat’s Republic**, Radisson Blu Hotel, 6, 5 street, Dubai.
Координаты карточки 2GIS: `25.186795, 55.26793`.

- [Исходная ссылка 2GIS](https://go.2gis.com/uzMq4)
- [Карточка места](https://2gis.ae/dubai/firm/70000001100982879)
- [Маршрут Waze](https://waze.com/ul?ll=25.186795%2C55.26793&navigate=yes)

## Запуск в PowerShell

1. Установите .NET 10 SDK.
2. Создайте бота через [BotFather](https://t.me/BotFather), получите токен.
3. `appsettings.json` хранится в Git только с безопасными значениями:

```json
{
  "Telegram": {
    "BotToken": "",
    "OwnerUserId": 0
  }
}
```

Реальный токен и положительный ID владельца указывайте только в локальном
`appsettings.Development.json`, исключённом из Git. Не заменяйте ими значения
в исходном `appsettings.json`. Для локального запуска сначала соберите приложение,
затем подключите локальную конфигурацию рядом с исполняемым файлом:

```powershell
Set-Location D:\Github\TelegramQuizArrangement
dotnet build -c Release
Copy-Item appsettings.Development.json bin\Release\net10.0\appsettings.json
dotnet bin\Release\net10.0\TelegramQuizArrangement.dll
```

На этом компьютере .NET 10 SDK установлен в `D:\Tools\dotnet10`, без изменения PATH.
Если `dotnet` не видит SDK, используйте `& 'D:\Tools\dotnet10\dotnet.exe'`
вместо `dotnet` в командах выше.

Runtime читает `appsettings.json` рядом с приложением. Конфигурация с реальными
значениями подключается только при запуске/деплое; исходный файл в Git остаётся
безопасным. Переменная `TELEGRAM_BOT_TOKEN` не используется.

4. Добавьте бота в группу и разрешите отправку сообщений и опросов.
5. Отправьте `/start`. Если в группе несколько ботов, используйте `/start@ИмяБота`.

Отключать Privacy Mode для команд не требуется. Для меню команд можно
задать через BotFather `/setcommands`: `start - Создать опрос о квизе`.
Остановить процесс: **Ctrl+C**.

Не запускайте одновременно несколько экземпляров с одним токеном.
Если ранее использовался webhook, удалите его перед запуском long polling.
Бот не удаляет webhook автоматически.

Часовой пояс можно переопределить:

```powershell
$env:QUIZ_TIME_ZONE = 'Asia/Dubai'
```

## Запуск в Docker

Расписание автоматически привязывается к последней группе, куда владелец
добавил бота, либо где владелец отправил сообщение от своего аккаунта.
Если бот уже добавлен, достаточно обычного сообщения (при Privacy Mode
ответьте на сообщение бота, чтобы Telegram доставил его боту).
При использовании нескольких групп выбирается последняя активированная
владельцем группа/тема; отдельная команда не обязательна.

Для смены группы расписания владелец отправляет `/setgroup@QuizArranger_bot`
в нужной группе (или теме). Команда не создаёт опрос. Назначение сохраняется
в Docker volume в `target.json` и переопределяет группу локального конфига
после перезапуска. Анонимные администраторы и другие пользователи не могут
сменить назначение; отправляйте команду от своего аккаунта.

При первом запуске скопируйте безопасный `appsettings.json` в `appsettings.Development.json` и укажите `Telegram:BotToken` и `Telegram:OwnerUserId`.
Docker Compose подключает этот файл как `/app/appsettings.json` только для чтения.
Локальный файл с реальными значениями исключён из Git; все `appsettings*.json` исключены из контекста сборки Docker. Секреты не копируются в образ.

```powershell
Set-Location D:\Github\TelegramQuizArrangement
docker compose up -d --build
docker compose logs --tail 30 bot
```

Бот работает в фоне и автоматически перезапускается, пока запущен Docker.
Включите автозапуск Docker Desktop при входе в Windows.
Остановите экземпляр в Rider, чтобы он не конкурировал с контейнером за обновления.

Остановить: `docker compose stop`. Запустить снова: `docker compose up -d`.
После изменения токена: `docker compose restart bot`.
После изменения кода: `docker compose up -d --build`.

## Необязательные формулировки OpenAI

В локальном `appsettings.Development.json` заполните `OpenAI.ApiKey` своим
ключом OpenAI API. Секция по умолчанию:

```json
"OpenAI": {
  "ApiKey": "",
  "Model": "gpt-6-luna"
}
```

Затем выполните `docker compose restart bot`. Не записывайте реальный ключ
в отслеживаемый `appsettings.json` или пример. Подписка ChatGPT не оплачивает
API: нужен отдельный API-аккаунт с доступом к модели и оплатой.
[gpt-6-luna](https://developers.openai.com/api/docs/models/gpt-6-luna)
поддерживает Responses API, Structured Outputs и `reasoning.effort: none`;
доступ конкретного аккаунта без ключа не проверен. Можно изменить `OpenAI.Model`,
но модель должна поддерживать те же параметры; иначе используется fallback.

Для каждой публикации `/start` в группе выполняется не более одного запроса:
`max_output_tokens=128`, `reasoning.effort=none`, `text.verbosity=low`,
строгий JSON `{q,y,n}`, `store=false`, таймаут 8 секунд, без retries и tools.
При пустом ключе запросов нет. Отправляются короткая инструкция из
`QuizWording.prompt.txt` и максимум последний принятый вопрос (до 70 символов);
история, ID, Telegram-токен, дата, время, место и ссылки в запрос не входят.
Skill разработчика в runtime не отправляется. Последний вопрос хранится только
в памяти процесса; точный повтор отклоняется без повторного запроса.

Вопрос проверяется по длине, формату и узкому списку запрещённых выражений; ответы — наборами по 16 вариантов явного
согласия/отказа. Код добавляет `🟩 ` и `🟥 `, воскресенье в 19:00 и дату;
место, Waze и темы остаются прежними. Неверный JSON, лишние поля, превышение
длины, неприемлемые слова, противоречивые ответы, refusal, incomplete, HTTP-ошибка
(включая 429), таймаут или повтор возвращают исходный безопасный опрос ДА/НЕТ.
Консервативный фильтр не использует whitelist всех слов и не даёт абсолютной гарантии
семантической уместности. Отдельный платный запрос модерации не выполняется.
Повторяющаяся подряд пара ответов заменяется локально; fallback тоже чередует 16 пар. Ротация общая для ручных и автоматических опросов, хранится в памяти и не требует запросов. Списки фраз передаются только в enum схемы, не дублируются в prompt.
В логи записываются числовые input/output usage и безопасный код причины (accepted, disabled_empty_key, http_429 и т. п.), без ключей
и сгенерированного текста. Отброшенные ответы также могут расходовать токены;
лимит ответа не ограничивает общее число вызовов `/start` или расходы за месяц.

Self-tests используют mock HTTP, проверяют параметры запроса, parsing,
ошибки, fallback, отсутствие запросов без ключа и постоянные параметры опроса.
Реальная AI-генерация не проверялась; расходы и тестовые опросы не запускались.

## Недельное расписание

Расписание работает внутри C#-процесса: **каждый четверг в 20:00 Asia/Dubai**
на ближайшее воскресенье в 19:00. Оно использует ту же AI-генерацию и безопасный
fallback, 🟩/🟥 без тире, полный русский месяц и неизменный маршрут Waze.
Ручной `/start` доступен отдельно и не влияет на недельные отметки.

Безопасный отслеживаемый пример:

```json
"Schedule": {
  "Enabled": false,
  "ChatId": 0,
  "ThreadId": null,
  "FirstRunLocal": null
}
```

В локальном `appsettings.Development.json` задайте `Enabled=true` и настоящий
отрицательный `ChatId` группы; `ThreadId` — положительный ID темы или `null`.
День/время фиксированы: четверг, 20:00, Asia/Dubai. `FirstRunLocal` имеет формат
`yyyy-MM-ddTHH:mm:ss` и должен указывать четверг 20:00. Текущая активация:
**15 октября 2026, 20:00 Dubai**, опрос на **18 октября, 19:00**; вчерашний
четверг при первой активации не публикуется. При пустом `FirstRunLocal` первая
активация сохраняет следующий четверг, без ретроактивной отправки.

После простоя берётся только последний прошедший четверг, не ранее активации,
и не более одного опроса. Догоняющая отправка допустима до воскресенья 19:00;
в 19:00 и позднее устаревший слот пропускается. Даже после долгого простоя
архивные недели не публикуются. Polling ограничен 30 секундами и сокращается
до ближайшего deadline расписания; сетевые операции и AI могут добавить задержку.
Проверка выполняется последовательно с обработкой команд; конкурентного изменения
AI-состояния нет. SIGTERM отменяет текущие операции для остановки Docker.

Состояние хранится в именованном Compose volume `schedule-data` в `/app/data`,
доступном пользователю `app`, и сохраняется при пересоздании контейнера.
`activation.json` закрепляет начало; `week-YYYY-MM-DD.json` содержит время слота,
игры и статус `reserved`, `sent`, `failed` или `uncertain`, без реальных chat/user ID.
Запись выполняется через временный файл, flush и атомарное переименование.
До AI и `sendPoll` резервируется слот. Перезапуск переводит незавершённый
`reserved` в `uncertain`; `failed`/`uncertain` автоматически не повторяются.
Ошибки записи отключают автоматические отправки до исправления и перезапуска.
Один процесс владеет блокировкой volume; параллельный экземпляр не стартует.

Telegram `sendPoll` не имеет ключа идемпотентности: при сетевом сбое неизвестно,
успел ли Telegram создать опрос. Это **не exactly-once**: reservation предотвращает
повторные автоматические попытки при сохранном volume ценой возможного пропуска,
в том числе при сбое после reservation, но до отправки. Удаление/потеря volume,
ручное изменение отметок или другой экземпляр с отдельным volume отменяют эту
защиту. Не выполняйте `docker compose down -v`, если хотите сохранить отметки.
Переконфигурация группы не сбрасывает недельную отметку. При необходимости
подтверждённый пропуск можно вручную компенсировать `/start`.

Synthetic self-tests проверяют активацию, timezone/deadline, границу воскресенья,
перезапуск, crash-reservation, атомарную сериализацию, ошибки хранилища и mock HTTP.
Живые Telegram/AI-запросы для проверки расписания не выполняются.

## Ограничения эксплуатации

Для работы бот должен оставаться запущенным на компьютере или сервере.
Позиция long polling хранится в памяти: перезапуск может обработать ещё
не подтверждённую команду повторно. Ошибки отправки не повторяются
автоматически, поскольку после сетевого сбоя результат отправки может быть неизвестен;
при необходимости вызовите `/start` снова. Живая проверка требует токена и группы.

Третий ответ отправляется общим `SendPoll` для ручных и автоматических опросов:
«Я Макс» → «Не могу так далеко планировать» → «Я в целом наквизился» →
«Мне всё с квизами понятно» → «У меня есть более интересные дела (шпилить в комп)»
→ снова сначала. Он не генерируется AI и не добавляет API-запросов.
Индекс хранится в `/app/data/third-answer.json`; self-tests используют отдельный
временный каталог и не расходуют боевой индекс. Следующая позиция заранее записывается
в уникальный временный файл с flush, но атомарно заменяет индекс только после
успешного ответа Telegram. Ошибка/неопределённый HTTP-результат сохраняет текущую
позицию. Исходный payload не изменяется: всегда два основных и один третий ответ.

Существует неизбежное окно между подтверждением Telegram и локальным commit:
если процесс/хранилище откажет в этом окне, при следующей публикации третий ответ
может повториться. При сетевой неопределённости он также может повториться,
если Telegram создал опрос без полученного подтверждения. Это не exactly-once;
повторных HTTP-попыток функция ротации не делает. Не удаляйте volume для сброса индекса.
## Закрепление опросов

Общий `PollPublisher` для ручных и автоматических публикаций сначала вызывает
`sendPoll` и сохраняет сдвиг третьего ответа, затем закрепляет `message_id` из
ответа Telegram через `pinChatMessage` с `disable_notification=true`.
После подтверждения нового pin снимает только предыдущий известный pin опроса
бота через `unpinChatMessage` с явным `message_id`. Чужие закрепления не трогаются,
`unpinAllChatMessages` и unpin без ID не используются.

Бот должен быть администратором группы с включённым правом **«Закреплять сообщения»**
(`can_pin_messages`): см. [pinChatMessage](https://core.telegram.org/bots/api#pinchatmessage)
и [unpinChatMessage](https://core.telegram.org/bots/api#unpinchatmessage).
Без права опрос публикуется обычным образом, старый pin остаётся, третья позиция
сдвигается; повторных `sendPoll` и дополнительных AI-запросов не выполняется.
Причина ошибки записывается безопасным статусом без секретов или тела API.

Состояние `/app/data/pinned-polls.json` в существующем Docker volume хранит
последний подтверждённый pin отдельно по chat/topic. При первом запуске бот не
угадывает старые закрепления, включая опросы до внедрения этой функции. Новый pin
сначала атомарно записывается на диск, затем выполняется unpin старого. Неудачная
очистка известного pin сохраняется и снова проверяется при следующей успешной
публикации/закреплении, в том числе после рестарта; удалённое или уже откреплённое
сообщение не приводит к повторной публикации. При сетевой неопределённости или
сбое между Telegram и сохранением состояния возможно сохранение лишнего pin;
успешный опрос от этого не теряется. Автоматической сверки чужих pins нет.

Mock HTTP проверки покрывают первую/следующую публикацию, разные группы и темы,
перезапуск, ошибки прав/сети/cancellation, удалённый старый pin, sendPoll failure,
сохранение третьего индекса и отсутствие unpinAll. Живые тестовые опросы не отправляются.
Накопленная позиция третьего ответа сохраняется: «Я Макс» — начало цикла при
первом внедрении, а не обязательный сброс после каждого обновления или ревью.
